### 정의

- **정렬된 순서를 유지하는 Map** 구현체
- Key를 기준으로 항상 **정렬 상태** 유지
- 내부 구현: **Red-Black Tree** (자가 균형 이진 탐색 트리)
- Java `java.util.TreeMap` / Kotlin에서도 동일하게 사용

### HashMap과의 차이

- **HashMap**: 순서 없음, 조회/삽입 평균 `O(1)`
- **TreeMap**: 정렬 순서 유지, 조회/삽입 `O(log n)`
- 정렬이 필요 없으면 HashMap이 빠름 → TreeMap은 **정렬·범위 조회가 필요할 때만** 선택

### 핵심 연산 (모두 O(log n))

- `firstKey()` / `lastKey()`: 최소·최대 Key
- `ceilingKey(k)`: k **이상**인 가장 작은 Key
- `floorKey(k)`: k **이하**인 가장 큰 Key
- `higherKey(k)`: k **초과**인 가장 작은 Key
- `lowerKey(k)`: k **미만**인 가장 큰 Key
- `subMap(a, b)`: 범위 [a, b) 조회

### 어떤 경우에 쓰는가

- **범위 조회**: "특정 값 이상/이하의 Key를 빠르게 찾아라"
- **정렬 유지 삽입/삭제**: 삽입할 때마다 자동 정렬 유지가 필요할 때
- **경계값 탐색**: 특정 값에 가장 가까운 원소 (ceiling/floor)
- 예: 좌표 압축, 스케줄링에서 가장 가까운 빈 시간 찾기, 구간 관리

### 우선순위 큐와의 구분

- **PQ**: 최솟값/최댓값 **하나**만 빠르게 꺼냄. 임의 원소 탐색·삭제 불가
- **TreeMap**: 정렬 전체를 유지하며 **임의 위치 탐색·삭제·범위 조회** 가능

> 
> ## 이진 탐색 트리 (BST) 기초
> 
> ### 정의
> 
> - 각 노드가 최대 **2개의 자식**을 가지는 트리
> - **정렬 규칙**: 모든 노드에서
>     - **왼쪽 서브트리**의 모든 값 < 현재 노드 값
>     - **오른쪽 서브트리**의 모든 값 > 현재 노드 값
> 
> ### 예시 구조
> 
> `8`을 루트로 `4, 12`를 삽입하면:
> 
> - `4 < 8` → 왼쪽 자식
> - `12 > 8` → 오른쪽 자식
> 
> ```
>     8
>    / \
>   4   12
> ```
> 
### > 탐색 방식
> 
> - 찾는 값이 현재 노드보다 작으면 → 왼쪽으로
> - 크면 → 오른쪽으로
> - 매 단계마다 탐색 범위가 **절반**으로 → `O(트리 높이)`
> 
> ### 핵심: 시간복잡도는 "높이"에 달렸다
> 
> - 균형 잡힌 트리: 높이 `log n` → 탐색 `O(log n)`
> - 한쪽으로 치우친 트리: 높이 `n` → 탐색 `O(n)`


## Red-Black Tree 기초 개념

### 정의

- **자가 균형 이진 탐색 트리**의 한 종류
- 각 노드에 **색(Red 또는 Black)**을 부여하고, 색 규칙으로 균형을 유지
- 삽입·삭제 시 색을 바꾸거나 회전(rotation)하여 높이를 `O(log N)`으로 유지

### 5가지 규칙

1. 모든 노드는 **Red 또는 Black**이다
2. **루트**는 항상 **Black**이다
3. 모든 **리프(NIL)** 노드는 **Black**이다
4. **Red 노드의 자식은 반드시 Black**이다 (Red가 연속될 수 없음)
5. 임의의 노드에서 그 하위 리프까지 가는 모든 경로의 **Black 노드 개수는 동일**하다 (Black-Height 일정)

### 균형이 유지되는 원리

- 규칙 4: Red는 연속 불가 → Red 노드는 전체 경로의 절반을 넘지 못함
- 규칙 5: 모든 경로의 Black 개수가 같음 → 경로 길이 편차 제한
- 두 규칙의 조합으로 **가장 긴 경로 ≤ 가장 짧은 경로의 2배** → 높이 `O(log N)` 보장

### 균형 복구 도구

- **Recoloring(재색칠)**: 노드 색만 변경
- **Rotation(회전)**: 좌회전 / 우회전으로 트리 구조 재배치
- 삽입·삭제로 규칙이 깨지면 이 두 도구로 복구

### 시간복잡도

- 탐색 / 삽입 / 삭제: 모두 `O(log N)`
- 삽입·삭제 시 회전 횟수: 상수 번으로 제한됨


## 회전을 왜 하는가 — 문제부터

### 출발점: 치우침이 문제였다

- BST에 `1,2,3,4,5`를 넣으면 오른쪽으로 쭉 늘어선 사향 트리 → 탐색 `O(N)`
- 원인: 한쪽 서브트리만 계속 길어지는데 **아무도 이를 되돌리지 않음**
- 필요한 것: "한쪽이 너무 길어지면 반대쪽으로 무게를 옮기는" 연산 → 이것이 **회전**

### 회전은 "부모 자리를 자식에게 넘기는" 동작

치우친 예를 봅니다. `y` 밑에 `x`, `x` 밑에 다시 노드가 달려 왼쪽이 무겁습니다.

```
      y  (루트, 왼쪽만 무거움)
     /
    x
   /
  A
```

- 문제: `y`는 왼쪽만 길고 오른쪽은 비어 있음 → 불균형
- 해결: `x`를 위로 올리고 `y`를 오른쪽으로 내림 → 양쪽으로 무게 분산

```
    x
   / \
  A   y
```

- 높이가 3에서 2로 줄었습니다. 이것이 회전이 하는 일입니다: **긴 쪽을 끌어올려 높이를 줄임.**

### 그런데 자식이 3개면? — B의 처리

`x`에 오른쪽 자식 `B`가 이미 있는 경우입니다.

```
      y
     / \
    x   C
   / \
  A   B
```

- `x`를 위로 올리면 `x`의 오른쪽 자리는 `y`가 차지해야 합니다.
- 그러면 원래 거기 있던 `B`는 밀려납니다. `B`는 어디로 가야 하는가?
- **대소 관계로 결정됩니다.** BST 규칙상 `x < B < y`입니다 (B는 x의 오른쪽 = x보다 큼 / y의 왼쪽 서브트리 = y보다 작음).
- `B`는 `x`보다 크고 `y`보다 작으므로 → **`y`의 왼쪽 자식**으로 붙으면 규칙이 그대로 유지됩니다.

```
    x
   / \
  A   y
     / \
    B   C
```

- 이것이 before/after 그림의 정체입니다. `B`의 이동은 임의가 아니라 **대소 관계가 강제하는 유일한 자리**입니다.

### 핵심: 회전은 정렬을 절대 깨지 않는다

- 회전 전후로 중위 순회(왼→루트→오른 순서로 읽기) 결과가 **항상 동일**합니다.
- 위 예: 회전 전 `A x B y C`, 회전 후 `A x B y C` → 동일
- 즉 회전은 **모양만 바꾸고 순서는 안 바꾸는** 연산입니다. 그래서 안전합니다.

## Red/Black은 왜 칠하는가 — 동기부터

### 회전만으로는 부족하다

- 회전은 "불균형을 고치는 도구"입니다. 그런데 **언제 회전해야 하는지**를 알려주는 기준이 없습니다.
- 매 삽입마다 전체 트리 높이를 재는 건 `O(N)`이라 너무 느립니다.
- 필요한 것: **국소적으로(주변 몇 개 노드만 보고) 불균형을 감지하는 값싼 신호** → 이것이 **색**입니다.

### 색은 "높이를 재지 않고 높이를 통제하는" 장치

- 직접 높이를 세는 대신, 노드에 Red/Black을 칠하고 **색에 대한 규칙**만 지키게 합니다.
- 규칙만 지키면 자동으로 "가장 긴 경로 ≤ 가장 짧은 경로의 2배"가 보장됩니다.
- 즉 색은 높이를 **간접적으로, 국소적으로** 제어하는 대리 지표입니다.

### 두 규칙이 높이를 잡는 방식

- **규칙: Red는 연속 불가** → Red 노드는 경로에서 절반을 넘을 수 없음
- **규칙: 모든 경로의 Black 개수 동일** → 경로 길이의 하한이 고정됨
- 조합 효과: 가장 긴 경로(Red+Black 섞임)도 가장 짧은 경로(Black만)의 **2배를 못 넘음** → 높이 `O(log N)`

### 왜 하필 2가지 색인가

- 색은 "이 노드가 높이 예산을 쓰는가(Black)/공짜로 끼어드는가(Red)"를 구분하는 **1비트 표시**입니다.
- Black만 높이 예산으로 계산하고, Red는 "Black 사이에 끼워 넣는 여유 노드"로 취급합니다.
- Red 연속을 금지하니 여유 노드가 무한정 쌓이지 못합니다 → 높이 폭주 방지

### 삽입을 Red로 시작하는 이유

- 새 노드를 **Black**으로 넣으면 → 그 경로만 Black이 1 늘어 규칙(모든 경로 Black 동일)이 즉시 깨짐 → 복구가 무거움
- 새 노드를 **Red**로 넣으면 → Black 개수는 안 변함. 운 나쁘게 부모도 Red일 때만 규칙 위반 → 복구가 국소적
- 그래서 삽입은 항상 Red로 시작합니다. **깨짐을 최소화하는 선택**입니다.
