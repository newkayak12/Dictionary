### 정의

- **정렬된 순서를 유지하는 Map** 구현체
- Key를 기준으로 항상 **정렬 상태** 유지
- 내부 구현: **Red-Black Tree** (자가 균형 이진 탐색 트리)
- Java `java.util.TreeMap` / Kotlin에서도 동일하게 사용

### HashMap과의 차이

- **HashMap**: 순서 없음, 조회/삽입 평균 `O(1)`
- **TreeMap**: 정렬 순서 유지, 조회/삽입 `O(log n)`
- 정렬이 필요 없으면 HashMap이 빠름 → TreeMap은 **정렬·범위 조회가 필요할 때만** 선택

### 핵심 연산 (모두 O(log n))

- `firstKey()` / `lastKey()`: 최소·최대 Key
- `ceilingKey(k)`: k **이상**인 가장 작은 Key
- `floorKey(k)`: k **이하**인 가장 큰 Key
- `higherKey(k)`: k **초과**인 가장 작은 Key
- `lowerKey(k)`: k **미만**인 가장 큰 Key
- `subMap(a, b)`: 범위 [a, b) 조회

### 어떤 경우에 쓰는가

- **범위 조회**: "특정 값 이상/이하의 Key를 빠르게 찾아라"
- **정렬 유지 삽입/삭제**: 삽입할 때마다 자동 정렬 유지가 필요할 때
- **경계값 탐색**: 특정 값에 가장 가까운 원소 (ceiling/floor)
- 예: 좌표 압축, 스케줄링에서 가장 가까운 빈 시간 찾기, 구간 관리

### 우선순위 큐와의 구분

- **PQ**: 최솟값/최댓값 **하나**만 빠르게 꺼냄. 임의 원소 탐색·삭제 불가
- **TreeMap**: 정렬 전체를 유지하며 **임의 위치 탐색·삭제·범위 조회** 가능

> 
> ## 이진 탐색 트리 (BST) 기초
> 
> ### 정의
> 
> - 각 노드가 최대 **2개의 자식**을 가지는 트리
> - **정렬 규칙**: 모든 노드에서
>     - **왼쪽 서브트리**의 모든 값 < 현재 노드 값
>     - **오른쪽 서브트리**의 모든 값 > 현재 노드 값
> 
> ### 예시 구조
> 
> `8`을 루트로 `4, 12`를 삽입하면:
> 
> - `4 < 8` → 왼쪽 자식
> - `12 > 8` → 오른쪽 자식
> 
> ```
>     8
>    / \
>   4   12
> ```
> 
### > 탐색 방식
> 
> - 찾는 값이 현재 노드보다 작으면 → 왼쪽으로
> - 크면 → 오른쪽으로
> - 매 단계마다 탐색 범위가 **절반**으로 → `O(트리 높이)`
> 
> ### 핵심: 시간복잡도는 "높이"에 달렸다
> 
> - 균형 잡힌 트리: 높이 `log n` → 탐색 `O(log n)`
> - 한쪽으로 치우친 트리: 높이 `n` → 탐색 `O(n)`


# Red-Black Tree 완전 정리

## 0. 한 줄 요약

- **Red-Black Tree = 삽입 순서와 무관하게 높이를 `O(log N)`으로 강제 유지하는 자가 균형 이진 탐색 트리(BST)**
- 노드에 **색(Red/Black)** 을 칠하고, 색에 대한 규칙만 지켜서 균형을 유지한다.

---

## 1. 왜 필요한가 (동기)

- BST의 모든 연산(탐색·삽입·삭제) 비용은 **트리의 높이**에 비례한다.
    - 높이 `log N` → 연산 `O(log N)` (빠름)
    - 높이 `N` → 연산 `O(N)` (느림)
- 문제: 일반 BST에 **정렬된 값**(`1, 2, 3, 4, 5`)을 순서대로 넣으면 한쪽으로만 늘어진 **사향 트리(skewed tree)** 가 된다.
    - 높이 = `N` → 탐색 `O(N)` → BST의 이점이 사라진다.
- 따라서 필요한 것: **삽입 순서와 무관하게 높이를 `log N`으로 눌러주는 장치**
- 그 장치가 Red-Black Tree.

```
정렬된 값 1,2,3,4,5를 일반 BST에 삽입:

1
 \
  2
   \
    3      ← 오른쪽으로만 늘어짐 (사향 트리)
     \
      4
       \
        5    높이 = N → O(N)
```

---

## 2. 핵심 아이디어 

- 실제 높이를 매번 직접 재는 것은 `O(N)` → 너무 느리다.
- 그래서 **높이를 직접 재지 않고 통제하는 대리 지표**가 필요하다.
- 그 대리 지표가 바로 **색**이다.
    - **Black** = 높이로 **세는** 노드 (높이 예산)
    - **Red** = Black 사이에 끼운 **여유 노드** (높이로 세지 않음)
- 규칙을 단순화하면 딱 두 문장이다:
    - **"Black 개수는 모든 경로에서 같게"**
    - **"Red는 연속으로 놓지 못하게"**
- 이 두 규칙만 지키면 트리 높이가 자동으로 `log N` 범위에 묶인다.

---

## 3. 5가지 규칙

|#|규칙|역할|
|---|---|---|
|1|모든 노드는 Red 또는 Black|색의 존재|
|2|루트는 항상 Black|경계 조건|
|3|모든 리프(NIL)는 Black|경계 조건|
|4|**Red의 자식은 반드시 Black** (Red 연속 불가)|높이 **상한** 제한|
|5|**임의 노드 → 리프 경로의 Black 개수는 모두 동일**|높이 **하한** 고정|

- 실질적으로 균형을 만드는 핵심은 **규칙 4와 5**.
- 나머지(1, 2, 3)는 경계 조건일 뿐이다.
- NIL 노드: 실제 데이터가 없는 리프 자리. 항상 Black으로 간주한다.

---

## 4. 두 규칙이 높이를 누르는 원리

- **규칙 5 (Black 개수 동일)** → 모든 경로의 Black 골격 길이가 같음 → 경로 길이의 **하한** 고정
- **규칙 4 (Red 연속 금지)** → 어떤 경로든 Red 개수 ≤ Black 개수 → 경로 길이의 **상한** 제한
- 두 규칙의 결합:
    - 가장 짧은 경로 = Black만 있는 경로 = `b`개
    - 가장 긴 경로 = Black `b`개 + 그 사이에 Red 최대 `b`개 = 최대 `2b`개
    - → **최장 경로 ≤ 최단 경로의 2배** → 높이 `O(log N)` 보장

---

## 5. 높이가 `O(log N)`인 수학적 증명

- **black-height(흑색 높이)**: 한 노드에서 리프까지 경로의 Black 노드 개수. 이 값을 `b`라 하자.
- black-height가 `b`인 트리에서 노드가 **가장 적은** 경우 = Red를 하나도 안 쓰고 Black만으로 꽉 채운 트리
    - 이 트리는 높이 `b`의 **꽉 찬 이진 트리** → 노드 수 = `2^b − 1`개
- 따라서 전체 노드 수 `N`에 대해:
    - `N ≥ 2^b − 1`
    - → `b ≤ log₂(N + 1)`
- 실제 높이는 규칙 4에 의해 `≤ 2b` 이므로:
    - 실제 높이 `≤ 2 · log₂(N + 1)`
    - → **높이 = `O(log N)`** ∎

---

## 6. 균형 복구 도구

삽입·삭제로 규칙이 깨지면 아래 두 도구로 복구한다.

### 6-1. 재색칠 (Recoloring)

- 노드의 **색만** 변경. 구조는 그대로.
- 주로 삼촌(uncle) 노드가 Red일 때 사용.

### 6-2. 회전 (Rotation)

- 부모-자식의 위치를 바꿔 **높이를 재분배**하는 연산.
- **정렬 순서(BST 규칙)를 절대 깨지 않는다.**

#### 우회전 (Right Rotation)

- 왼쪽이 무거울 때, 왼쪽 자식 `x`를 위로 끌어올리고 부모 `y`를 오른쪽 아래로 내린다.

```
      y                 x
     / \               / \
    x   C    →        A   y
   / \                   / \
  A   B                 B   C
```

- **핵심은 `B`의 재배치**:
    - 회전 전: `B`는 `x`의 오른쪽 자식 → `x < B`
    - 동시에 `y`의 왼쪽 서브트리 → `B < y`
    - 즉 `x < B < y`
    - 회전 후 `B`를 `y`의 왼쪽 자식으로 붙이면 → BST 규칙 그대로 유지
- `B`의 이동은 임의가 아니라 **대소 관계가 강제하는 유일한 자리**다.

#### 좌회전 (Left Rotation)

- 우회전의 완전한 대칭. 오른쪽 자식을 위로 끌어올린다.

```
    x                   y
   / \                 / \
  A   y      →        x   C
     / \             / \
    B   C           A   B
```

#### 회전이 정렬을 안 깨는 이유

- 회전은 **부모-자식 관계만 재배치**하고 값의 대소 순서는 건드리지 않는다.
- **중위 순회(in-order) 결과가 회전 전후로 동일**하다. (위 예: 회전 전후 모두 `A x B y C`)

---

## 7. 삽입 (Insertion)

### 왜 새 노드는 항상 Red인가

- **Black으로 넣으면**: 그 경로만 Black이 +1 → 규칙 5(Black 개수 동일)가 **항상** 깨짐 → 복구가 무겁다.
- **Red로 넣으면**: Black 개수는 그대로 → 규칙 5는 안 깨지고, **부모가 Red일 때만** 규칙 4 위반 → 복구가 국소적이다.
- 결론: 규칙 위반을 최소화하는 선택이 **Red 삽입**이다.

### 삽입 후 복구 케이스 (규칙 4 위반 시)

새 노드의 **삼촌(부모의 형제) 색**에 따라 갈린다.

|Case|조건|복구 방법|
|---|---|---|
|1|삼촌이 **Red**|부모·삼촌을 Black으로, 조부모를 Red로 재색칠 → 조부모에서 위로 재검사|
|2|삼촌이 **Black**, 꺾인 모양(triangle)|부모를 회전시켜 일직선으로 변형 → Case 3으로|
|3|삼촌이 **Black**, 일직선(line)|조부모 기준 회전 + 부모·조부모 색 교환|

### 삽입 예시: `10, 20, 30` 순서대로

```
[10 삽입]        [20 삽입]         [30 삽입 → Red 연속 위반]

  10(B)            10(B)              10(B)
                      \                   \
                     20(R)               20(R)
                                            \
                                           30(R)  ← 부모도 Red! 규칙 4 위반

→ 삼촌 = NIL(Black), 일직선 형태 → 좌회전 + 재색칠

[복구 완료]
      20(B)
     /     \
   10(R)   30(R)   ← 균형 트리. 규칙 4·5 모두 만족
```

- 회전 전: 오른쪽으로 3단 늘어진 사향 트리(높이 3)
- 회전 후: 높이 2의 균형 트리
- **사향 트리로 갈 뻔한 순간을 색 규칙이 감지 → 회전으로 되돌린 것**

---

## 8. 삭제 (Deletion)

- 삽입보다 케이스가 복잡하다.
- 제거되는 노드가 **Black**이면 그 경로의 Black 개수가 줄어 규칙 5가 깨진다.
- 이를 대체하는 노드에 **"이중 흑색(double black)"** 개념을 부여하고, **형제 노드 색**과 **형제의 자식 색**에 따라 여러 케이스로 분기하여 재색칠 + 회전으로 해소한다.
- 핵심만: 삽입은 **삼촌 색**으로 분기, 삭제는 **형제 색**으로 분기.

---

## 9. 시간복잡도

|연산|시간복잡도|
|---|---|
|탐색|`O(log N)`|
|삽입|`O(log N)`|
|삭제|`O(log N)`|
|삽입·삭제 시 회전 횟수|상수 번(`O(1)`)으로 제한|

---

## 10. 어디에 쓰이는가

- **Java `TreeMap` / `TreeSet`** 의 내부 구현이 Red-Black Tree다.
- 정렬 유지 + 범위 조회 + 경계값 탐색(ceiling/floor)이 모두 `O(log N)`.
- 코딩 테스트에서는 직접 구현보다 `TreeMap`/`TreeSet`을 도구로 쓰는 경우가 많다.

---

## 11. 전체 흐름 요약 (복습용)

1. BST는 높이에 성능이 좌우된다 → 정렬 입력 시 사향 트리 → `O(N)` 문제
2. 높이를 직접 재는 건 느리다 → **색을 대리 지표로** 사용
3. Black = 높이로 셈, Red = 여유 노드
4. 규칙 5(Black 개수 동일) = 하한 고정 / 규칙 4(Red 연속 금지) = 상한 제한
5. 두 규칙의 결합 → 최장 ≤ 최단 × 2 → 높이 `O(log N)`
6. 규칙이 깨지면 **재색칠 + 회전**으로 복구
7. 새 노드는 **Red 삽입** (규칙 위반 최소화)
8. 회전은 **중위 순회 불변** → 정렬을 안 깨고 높이만 재분배
